# v0.21.0

**Release Date:** 2026-08-24

## Highlights

- **Gigapixel CZIs render in napari.** New spatial Y/X tiling in
  `read_stacks(..., use_dask=True)` breaks single 2D planes bigger than
  256 MB uncompressed (e.g. 93,555 × 138,996 uint16 ≈ 24 GB per channel)
  into ROI-based Dask chunks. Only the tiles that intersect the current
  viewport are read, instead of full planes.
- **Native multiscale pyramid reader.** `read_stacks_multiscale` returns
  one lazy Dask array per stored pyramid level in the shape napari's
  `add_image(..., multiscale=True)` accepts. Falls back to synthesised
  coarser levels via libCZI's C++ resampler when the coarsest stored
  level is still larger than the GPU texture limit.
- **`pylibCZIrw`-only pyramid detection.** `get_pyramid_zooms` enumerates
  subblock headers with `SubBlockInfo.get_zoom()` in ~20 ms — no
  `czifile` dependency, no extra tools.
- **Reader package split.** The 1,550-line `read_tools.py` is broken
  into focused modules. A backward-compat facade keeps every existing
  import path working, so downstream code such as `napari-czitools`
  needs no changes.
- **Two subtle bug fixes** unlocked gigapixel viewing: `int()` truncation
  matching libCZI, and layer-0-native ROI coordinates in the tiled
  reader. Both were required for napari to zoom into a 105 GB file
  without shape-mismatch or wrong-pixel errors.

## Added

- `src/czitools/read_tools/pyramid.py`
  - `get_pyramid_zooms(filepath) -> list[float]` — returns sorted-descending
    unique zoom factors stored in the CZI. Drops any level below
    `pylibCZIrw`'s minimum readable zoom (0.01) so every returned value
    is hittable by `CziReader.read(zoom=...)`.
  - `read_stacks_multiscale(filepath, ...)` — one lazy array per pyramid
    level, coarsest last, in a shape ready for napari multiscale.
    Optional `max_coarse_edge` (default 8192) forces additional
    synthetic coarser levels when needed.
  - `PyramidLevel` dataclass — per-level `zoom`, `stored`, `y`, `x`.
- `src/czitools/read_tools/stacks.py`
  - `_read_tile_delayed`, `_compute_tile_extent`, `_plan_tile_grid`,
    `_build_tiled_plane_dask` — private helpers implementing spatial
    Y/X tiling on top of `pylibCZIrw`'s ROI reads.
  - New `tile_size: int = 4096` parameter on `read_stacks`,
    `read_stacks_list`, and `read_stacks_stacked`.
- Documentation
  - `README.md` gained a multiscale/tiling quick-start snippet.
  - `docs/usage.md` gained new sections on spatial Y/X tiling and
    multiscale pyramid reading, including the coordinate-space and
    rounding caveats developers need to know.
  - `_notes/MODERNIZATION_TODO.md` items 3b and 3c marked complete with
    a "lessons learned" block capturing every non-obvious insight from
    implementation.

## Changed

- `src/czitools/read_tools/` — the previously monolithic `read_tools.py`
  (~1,550 lines) is split into:
  - `_helpers.py` — shared type aliases, axis constants, coord helpers
  - `array6d.py` — `read_6darray`
  - `stacks.py` — `read_stacks*` plus tiling infrastructure
  - `field_well.py` — `read_field`, `read_well`, HCS resolution
  - `attachments.py` — `read_attachments`
  - `tiles.py` — mosaic tile reader
  - `pyramid.py` — new multiscale reader
  - `read_tools.py` — backward-compat facade re-exporting the public API
- `read_stacks` no longer reads a whole plane just to peek at dtype/shape.
  A 1×1 ROI probe replaces the old full-plane sample read. On a
  93,555 × 138,996 gigapixel file this alone drops multiscale
  construction from ~164 s to ~2.5 s.
- Typing modernised: PEP 604 (`X | None`) and PEP 585 builtin generics
  (`list[str]`, `dict[str, int]`) throughout the split modules.

## Fixed

- **Shape prediction now matches `pylibCZIrw` exactly.** The reader
  used `round(rect * zoom)` to predict the shape of a zoomed read.
  libCZI actually uses `int()` truncation, so at zooms like `0.037037`
  the prediction overshoots by one pixel and the Dask graph fails with
  `ValueError: could not broadcast input array from shape (3464, 5147)
  into shape (3465, 5148)`. Every path that predicts an output shape
  now uses `int()` truncation.
- **ROI coordinates are now correctly layer-0 native.** The tiled
  reader previously laid out the grid in *zoomed* coordinates, then
  handed those tuples to `pylibCZIrw.CziReader.read(roi=...)` — which
  interprets ROIs in layer-0 space. At non-1.0 zoom this silently
  returned pixel arrays with the wrong content and shape. The builder
  now works entirely in layer-0 coordinates and converts requested tile
  edges via `ceil(tile / zoom)`.
- **Sum-of-truncations vs truncation-of-sum consistency.** At zooms
  like `1/3` the direct `int(rect * zoom)` estimate can differ from the
  actual tile-composed total by 1–3 pixels. `_plan_tile_grid` is now
  the single source of truth for per-row/per-column tile sizes; both
  the Dask graph and the outer coordinate arrays consume its output.
  This eliminates the `CoordinateValidationError: conflicting sizes for
  dimension 'Y': length 31182 on the data but length 31184 on
  coordinate 'Y'` that occurred when opening the Mouse Kidney file's
  1/3-zoom pyramid level in napari.

## Backward compatibility

All existing public imports continue to work unchanged:

```python
from czitools.read_tools import read_tools
result = read_tools.read_stacks(...)          # unchanged
data, mdata = read_tools.read_6darray(...)    # unchanged
```

The subpackage split is behind a facade in `read_tools/read_tools.py`.

## Verification

- 343/343 existing tests pass on Windows and Linux.
- Pixel parity between whole-plane and tiled reads verified at zoom 1.0
  on grayscale, RGB, and scene-based test CZIs.
- Pixel parity at stored pyramid zooms verified on `DTScan_ID4.czi`.
- Multiscale reader validated end-to-end on the 105 GB
  `Mouse Kidney_40x0.95_3CD_JK.czi` (93,555 × 138,996 uint16, 3
  channels): detection ~0.02 s, 5-level pyramid built in ~2.5 s,
  napari renders and pans without OOM.
