# czitools v0.27.2

Released: 2026-10-30

This release makes OME-NGFF 0.6 the default for new image and HCS plate
exports. It also adds explicit version profiles and metadata guardrails
to prepare for future specifications without enabling draft output.

## Changed

- Both ngff-zarr and ome-zarr-py default to OME-NGFF 0.6 across all four
  CZI conversion APIs, including native CZI pyramids and ngff-zarr OZX
  output.
- Low-level ome-zarr-py metadata is finalized with ngff-zarr's 0.6
  converter, preserving channels, physical scaling, and pyramid
  translations without rewriting pixel data.
- OZX exports no longer silently downgrade to 0.5. Packaging an existing
  directory preserves its declared version and rejects version mismatches.
- Export and validation use explicit version profiles. Unsupported versions
  are rejected instead of falling back to an older schema.
- Internal axis descriptions no longer infer time semantics for unknown
  axes. Single-image writers require explicit TCZYX layouts and reject
  unsupported arrays or supplied pyramids before overwriting output.
- Metadata validation checks hierarchy versions, released-profile axis
  layouts, Zarr format, and channel colors and display windows. Validation
  also supports read-only OZX archives and explicit legacy stores.
- HCS metadata and layout checks run before removing existing output.
  Rejected archive packaging preserves the source and existing archive.
- Native ngff-zarr output no longer receives the obsolete version-tag
  rewrite. The ome-zarr-py path retains genuine 0.6 metadata conversion.

## Compatibility

- Existing stores are not migrated or modified by upgrading czitools.
  Reconvert from the original CZI to obtain the updated metadata.
- OME-NGFF 0.6 remains the stable default. Draft 0.9 exports are disabled
  until the exact target version is supported and tested end to end.
- Legacy output remains available only through explicit, supported version
  and backend combinations. Use a separate destination for compatibility
  exports rather than relabeling an existing store.
- Original CZI XML preservation remains opt-in via
  `preserve_original_metadata=True`.
- The export extra continues to require `ngff-zarr>=0.47.0`.
- Python 3.12, 3.13, and 3.14 remain supported.

## Example

```python
from czitools.export_tools import convert_czi2hcs_ngff, validate_ome_zarr

output = convert_czi2hcs_ngff("plate.czi")
assert validate_ome_zarr(output)
```
