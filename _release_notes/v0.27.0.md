# czitools v0.27.0

Released: 2026-10-13

This release reduces active pixel-memory requirements for large CZI exports
and avoids regenerating pyramid levels already stored in the source file.

## Added

- The converter GUI offers 256, 512, or 1024-pixel output chunks, with 512
  as the default. Output chunks are independent of CZI read tile size.
- Auto Dask concurrency uses available RAM and CPU capacity. Manual GUI
  values from 1 to 32 override Auto; the selected pool size is displayed and
  logged, for example `8 (Auto)`.
- Both single-image Python writers accept `worker_count=0` for Auto and
  supplied lazy pyramid levels through `source_multiscales`.

## Changed

- Individual-image GUI exports use lazy spatial CZI ROI reads, with tiles
  up to 4096 pixels and a 32 MiB per-tile budget, instead of loading entire
  scenes into RAM.
- Native CZI pyramid reuse is enabled by default for individual images
  with both ngff-zarr and ome-zarr-py. Both HCS backends also reuse stored
  levels. Native pixels, scales, translations, and approximately 3x ZEN
  pyramid steps are preserved without replacement 2x downsampling.
- Only a missing coarse tail is synthesized, targeting a longest edge of
  512 pixels within libCZI's supported zoom range. Files without stored
  coarse levels use the same lazy reader fallback.
- NGFF directory exports write the base directly to the destination and
  append subsequent levels. When regeneration is selected, each level uses
  its previously written predecessor. Supplied CZI levels also write
  directly to `.ozx`; regenerated archives retain disk-backed staging.
- The export extra requires `ngff-zarr>=0.47.0`. Export and full extras
  include `psutil>=5.9` for memory-aware worker selection.
- README and installation/usage documentation cover the new workflow.

## Fixed

- The GUI no longer uses an eager full-scene read for individual exports.
- Cache and write progress are reported, including elapsed graph
  preparation and archive staging. Temporary caches are removed on success
  or failure.

## Operational Notes

- To regenerate an individual image's pyramid, uncheck **Reuse CZI pyramid**.
  Raw-array writer calls retain their generated-pyramid behavior.
- Auto reserves the larger of 2 GiB or 20% of total RAM, budgets 1 GiB per
  worker from the remaining available RAM, and caps concurrency at half
  the logical CPU count and eight workers, with a minimum of one. If RAM
  metrics are unavailable, it uses at most two workers.
- Auto is a starting heuristic, not a hard process-memory cap or a pool
  that resizes during conversion. The displayed count is the selected pool
  size, not instantaneous busy-thread utilization. HCS retains its existing
  field-concurrency policy.
- Native reuse still decodes CZI pixels and encodes the destination; it is
  not a compressed-byte copy. Very large task graphs still need RAM, and
  regenerated archives require space for intermediate caches and output.
- A full >100 GB conversion or throughput benchmark has not been run.

## Upgrade

```bash
python -m pip install --upgrade "czitools[omezarr-gui]"
```

Python 3.12 and 3.13 remain supported.
